# frontend/src/features/ledger

## Purpose

- Owns shared transaction browsing, detail, and entry workflow UI.

## Implicit Contracts

- REST transaction responses own classes, shapes, roles, display titles, and amounts; every transaction surface uses the display title, and contextual overflow tooltips include current account FQNs. Shared views must not derive totals, and unavailable USD renders as `N/A`.
- Transaction pages are disposable in-memory snapshots keyed by normalized request parameters, including a future date anchor while paging its projected sequence. Keep a displayed snapshot during a failed refresh, discard responses superseded by a newer page generation or background refresh for the same page, preserve errors created after an ordinary load began, and do not let detail or entry-only URL changes orphan an equivalent request.
- Ledger lookups are a shared app-wide snapshot; a route that starts their load must let the result publish after unmount so route-independent editors cannot inherit a stranded loading state.
- Routes own filter, sort, pagination, and future-anchor URL semantics. This feature owns only the composable `transaction` detail parameter, preserving unrelated parameters and fetching a selected persisted transaction absent from the current page snapshot; response-local recurring projections open from their list record without a URL parameter or detail fetch. List-state writes retain one overlay history entry so Back dismisses detail onto the updated list state, and a terminal lookup failure releases detail loading so the shared panel can render its reference-light fallback.
- Transaction-page snapshots include the selected sort field and direction in their identity; date jumping is available only for initiated-date descending order and accepts server-projected future recurring rows. Projected rows render as Expected and open their response-local record in read-only detail; only the server-marked next projection offers definition-level Defer, while later projections have no actions. Date jumping retains button identity while loading so completion restores focus to the activated control. Closing the class popover restores focus without opening its trigger tooltip; closing the sort popover restores focus to its trigger unless an outside interaction targeted another control.
- Detail is read-only and follows the [transaction detail disclosure rules](../../../../docs/webui-design.md#transactions). Reopening its transaction row closes it through the row activation path without a competing outside-pointer close and restores focus, while register embeddings may keep the same transaction open as focus moves between its records. URL-first detail selections focus the panel; register row selections keep row focus while walking across transactions. An intentional newer focus target wins over deferred panel autofocus, source-seeded recurring editors count as inside the detail overlay boundary, and embeddings must retain the list restore target and transaction-row/pagination hooks used when a changed row disappears.
- Detail resolves recurring provenance through exact occurrence reads or the projection's active definition, shares the loaded projection definition with its Defer dialog and retries a failed projection read when Defer opens, links active definitions to editor-opening management routes, and renders cancelled definitions without a dead link or hiding the transaction while provenance loads.
- Register lifecycle refreshes may retain the complete replacement transaction while invalidating dependent register pages so detail stays complete without a redundant fetch.
- Category/Tag report previews reuse browser rows and read-only detail without paging, Edit mode, row mutation actions, sticky scrolling, or browser controls.
- Transaction rows and detail consume one applicability matrix and follow the [transaction action-placement rules](../../../../docs/webui-design.md#transactions). Materialized expected occurrences confirm through one actual-date dialog whose default is the scheduled date; list, transaction detail, and register detail submit the same value, and REST owns date-domain validation. Confirmation and projection-defer refreshes retain the displayed transaction snapshot while their pending dialogs stay mounted. A recurring-editor overflow launch dismisses its menu before transferring focus into the editor.
- Recurring-definition capture copies active reusable records in response order without dates, settlement, provenance, transaction identity, or transaction-only metadata.
- Edit-mode selection is page-local. Account Replace follows the [Transaction Edit mode workflow](../../../../docs/webui-design.md#transaction-edit-mode); REST remains authoritative, completed counts drive feedback, affected account caches are invalidated from selected snapshots plus the explicit replacement, and the current-page refresh replaces per-transaction detail reads. A failed or superseded post-replacement page refresh clears the affected selection and leaves the current page stale for retry instead of republishing stale source choices; retained inline amount conflicts block replacement so their winner-backed snapshots cannot be superseded. Apply other narrow record mutations only to eligible record roles; other structural changes and full transaction replacement remain in the entry editor. Row-amount editing replaces the complete active transaction atomically, preserves record identities and the loaded ETag, and keeps invalid or failed input inline.
- Transaction editor baselines carry record IDs, retained hidden valuations, and the timestamp-backed ETag through shorthand, advanced, split, and amount-edit transformations; stale refreshes replace hidden baselines with the winner so retries cannot restore superseded values. Retained records omit provenance, new records omit identity, and imported records remain fixed identity anchors that cannot be split, merged, or removed.
- Concurrent replacement behavior follows [the transaction-entry stale-write UX](../../../../docs/webui-design.md#transaction-entry). Ledger owns the winner-backed editor baseline and retry gate, restores a cancelled winner only on the explicit conflict retry and requires review of the restore response before replacement, keeps shorthand tabs unavailable after structural recovery, pins retained inline-conflict rows outside cached query membership, prevents pagination from unmounting a retained inline draft, reapplies the query with row-removal focus fallback on discard, maps Advanced drafts onto winner identities, and never downgrades a newer in-memory transaction snapshot.
- Successful transaction mutations use the shared refresh helpers: invalidate affected reference and register snapshots, including every loaded transaction version in a conflict retry and explicitly identified accounts not present in available transaction snapshots; refresh the current transaction view, featured balances, and overview; and mark sibling transaction pages stale before the refresh can republish the current page. Recurring-definition invalidation also reloads provenance retained by a mounted transaction detail.
- Recurring-definition mutations advance occurrence catch-up before marking transaction pages stale; mounted browsers keep their snapshots while materializing newly due occurrences and refetching. A failed post-mutation catch-up clears transaction pages and reports the successful mutation with incomplete refresh instead of leaving an actionable stale projection. Deferring a projected row reconciles open response-local detail from the same definition against the refreshed page, closes removed projections, and leaves other definitions untouched while refreshing mounted recurring-definition snapshots.
- A failed date-jump preflight leaves the current page visible and attaches retry feedback to that retained page; after an anchor is established, page failures and retries remain scoped to the anchored sequence.
- Background page refreshes preserve the mounted snapshot, serialize same-page results so superseded callers observe the winning refresh, synchronize page-local selection snapshots from successful same-page results, and expose row-visibility completion callbacks to their workflow owners.
- When an action refresh remounts its source row, focus restoration re-resolves the live overflow trigger; confirmed occurrence rows restore by transaction identity after date reordering, while removed rows use the prior index or pagination fallback without a competing detail-panel cleanup target.
- Entry drafts persist only UI form values per tab. Initialization defaults neither create a draft nor overwrite entered values or take focus after interaction.
- Entry modal closure prefers an explicit stable launch target over transient pointer targets, then falls back to the owning list region and Transactions navigation.
- The entry modal's recent-transaction rail is passive, remains outside the tab order, and exposes account-title context without adding controls.
- Picker-created entities remain local overlays until shared lookups refresh; client checks only shape, while REST remains the validation authority.
- A picker whose controlled ID arrives before its options displays the selected label when lookup data catches up without overwriting typed input.
- Currency filters offer active account currencies plus typed codes, retain repeated canonical URL values, and leave definitive code validation to REST.

## Boundaries

- Owns: ledger display components, transaction snapshots and refresh coordination, detail loading, edit-mode behavior, entry UI mapping, and lookup picker behavior.
- Does not own: generated API setup, accounting validation or persistence, route filter semantics, or the app-shell-owned `entry` URL lifecycle and entry-save orchestration.
