# github.com/mishamsk/mina/internal/services/transactions

## Purpose

- Owns transaction and journal-record use cases plus reusable transaction-semantic classification.

## Implicit Contracts

- Create, replace, and reference-sensitive bulk operations hold a shared reference lease across validation and persistence; concurrent material bulk changes to one transaction surface as retryable conflicts. Cancellation, restoration, deletion, settlement, reconciliation, and backfill are fact-only mutations and do not take that lease.
- Complete replacement validates one desired transaction aggregate while reconciling journal records by explicit identity: retained IDs must be unique active members of that transaction, and omitted IDs are removals rather than positional matches.
- Existing-record replacement input cannot change creation provenance. Store replacement reports imported or linked omission blockers atomically; the service translates them into the rule that those identities cannot be removed ordinarily, while whole-transaction deletion removes active links without detaching importer metadata.
- Writes resolve active account, category, tag, and member references before persistence, including account-currency compatibility, then enforce per-currency balance and the semantics in [`docs/accounting-semantics.md`](../../../docs/accounting-semantics.md).
- Create derives missing `amount_usd` at the initiated date and preserves supplied values. Without an explicit valuation, replacement carries forward the stored valuation, including null, for an unchanged retained amount/currency pair; new or changed pairs derive a missing valuation at the initiated date. Backfill atomically changes only unresolved, non-tombstoned values, using the posted date when present and otherwise the initiated date; it must not rewrite historical valuations.
- Derived display USD amounts use the same signed record contributions as native amounts. A missing USD contribution or USD aggregation overflow makes that currency's USD display unavailable without suppressing its native amount.
- Exchange display titles identify the involved balance accounts when each side resolves to one account; a side spanning multiple accounts falls back to the currency-marker pair. Markers use conventional narrow symbols and fall back to stored codes when no symbol is available or the pair's symbols collide.
- Account-type changes and bulk category or record-account reassignment revalidate every affected transaction's semantics, so a locally valid record edit cannot invalidate its siblings. Transaction account replacement additionally requires one non-system source on every selected transaction, permits owned/party interchange or flow-to-flow replacement only, and validates every resulting aggregate before persistence.
- Account bulk-search composition loads the selected transactions in one repository batch and exposes only transaction-owned common-source and affected-currency facts; the account service retains candidate loading, type/currency eligibility, hidden policy, and ranking.
- Settlement dates are normalized only for owned and party records: omitted create defaults use the initiated-date timestamp, while later mutation defaults use one operation-clock instant; supplied timestamps are preserved. The store atomically rejects ordinary bulk, replacement, or deletion mutations of expected recurring transactions and lifecycle changes that became invalid after service validation.
- Transaction lists parse and resolve the boolean filter DSL from [`docs/transaction-filter-dsl.md`](../../../docs/transaction-filter-dsl.md), including clock-relative values, hidden active references, and unquoted stable-ID literals for entity-valued fields; malformed literals fail validation while well-formed missing IDs match nothing. The syntax cap excludes quoted dictionary-reference payloads so supported names remain expressible. One shared reference lease covers the complete resolution tree and projected evaluation, so name/FQN entity terms resolve to stable IDs, ID literals compare directly, and scopes match FQNs from the same reference snapshot; persisted-only lists do not acquire the recurring-state lease. Supplying any expression disables the default expected-transaction exclusion, and the resolved tree drives both store SQL and non-persisted recurring-projection matching. Transaction lists reject missing or inactive human-readable dictionary filters rather than treating them as empty results; record searches validate positive dictionary IDs as active references, batch sibling records for the selected page, and derive display titles through transaction classification. A transaction tombstoned between those queries leaves its selected rows without optional presentation fields instead of invalidating the page. Both support updated-date ordering with their own identities as stable tiebreakers. Every material transaction metadata, lifecycle, valuation, or nested-record mutation advances the transaction update timestamp once; exact no-ops preserve all timestamps. Account-scoped search maps an invalid target account to not found, and only it may request running balances.
- Complete replacement uses the shared strong ETag representation of the canonical transaction update timestamp, compares the caller token to its loaded aggregate before validation, and passes that snapshot timestamp to the store's atomic write comparison. Missing-precondition and stale-precondition transport statuses belong to `internal/httpapi`.
- Transaction-list deep links use exact Category or Tag FQNs for leaves and descendant-scoped FQNs for groups; scopes include hidden active descendants.
- Transaction lists never materialize recurring occurrences. Future initiated-date anchors receive read-only projections before the resolved filter, standing class, and search predicates apply. The projector owns shared reference and recurring-state lease acquisition, including re-entry from a filtered list's existing shared reference scope, and marks the definition's anchor row before filtering. Projection participates in server-owned ordering, anchor pagination, and total counts; projections have no future USD valuation, and the default no-filter predicate excludes Expected rows after generation. An initial request without an offset seeks to the anchor page and later explicit offsets address that merged sequence. Persisted and projected rows share one recurring snapshot.
- Transactions created by recurring definitions carry the definition ID directly. Store reads hydrate its FQN and active availability even after cancellation; opt-in tombstoned reads return the deleted transaction and its deletion-time record shape with the same provenance, while future projections carry it without persistence.
- Successful create and materially changing replacements call the injected currency-usage callback, which composition uses to invalidate dependent exchange-rate-loading caches; exact no-op replacement skips it.

## Boundaries

- Owns: transaction validation, lifecycle and settlement normalization, reference-error translation, semantic classification and display derivation, record-search validation, bulk record rules, and transaction-owned account-search facts.
- Does not own: dictionary state or caches, exchange-rate lookup, persistence implementation, scheduling, or transport mapping.
