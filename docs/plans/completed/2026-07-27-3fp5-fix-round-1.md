# Plan: 3fp5 fix round 1 — generalize the live URL-sync fix and harden its tests

Operator-review follow-up to the completed `docs/plans/completed/2026-07-26-3fp5-search-url-detail-preserve.md`. The shipped fix is correct on the Transactions page but was not generalized to the identical drill-down surface, left half of the page's own filter writers on stale merge bases, and pinned the race with a fragile test. This plan closes those gaps. Implementation only.

## Plan Context

- Do not run review-loop.
- Ground truth: `docs/webui-design.md` (including the new overlay-preserving shareable-state URL write rule in Interaction Rules → Tables and filtering), `docs/frontend-architecture.md`, `docs/TESTING.md`.
- Audit findings driving this plan (all verified with file:line by the operator's review audit):
  1. `frontend/src/features/reference/reference-drilldown-page.tsx` (~lines 299–347) still uses the render-stale `setSearchParams` functional updater for its debounced `TransactionSearchInput` write and filter writes. Category/tag/member drill-down pages embed the same shared browser with the same detail panel and the route-independent `?entry=` modal, so they keep the exact bug 3fp5 fixed on Transactions.
  2. In `frontend/src/pages/transactions-page.tsx`, `setTransactionClassFilter`, `setHideExpected`, and `clearFilterChips` still spread the render-time `filters` object into `setTransactionFilters`, so a late class/hide-expected/clear write preserves `transaction=`/`entry=` but can revert a just-committed `q`. `addEntityFilter` was already converted to live reads; these three must match it.
  3. The live-read concept now exists in multiple spellings (`readLiveSearchParams` in `transactions-page.tsx`, `window.location.search` reads in `app-shell.tsx`). Extract one shared helper in `frontend/src/features/ledger` (next to `writeTransactionFiltersToSearchParams`) and use it at the page-level call sites; route pages stay thin per `docs/frontend-architecture.md`. Do not rework `app-shell.tsx`'s own internal reads.
  4. The double `setSearchParams` (replace-without-overlay-param, then push-with-it) in `setSearchFilter` is only safe because both calls run synchronously in one tick, so React never renders the intermediate `entry`-less state that would make `app-shell.tsx` close the modal and discard the draft. This invariant is invisible at the call site — it needs a code comment naming it (synchronous, same-tick, never await between the calls).
  5. Test fragility in `frontend/tests/e2e/transactions-page.spec.ts`: (a) the `window.setTimeout` monkeypatch matches the literal `timeout === 300`, would silently capture any other 300ms timer scheduled first, and never restores the original when no match appears; (b) the first race test ("search then open detail") likely passes pre-fix too, because the detail-open re-render re-arms the debounce with a fresh closure — it must use the same deterministic capture mechanism as the split-editor test so it actually discriminates; (c) the new tests hand-roll `expect.poll` over URL params instead of the existing `expectTransactionsPageUrl` helper, and `createSearchRaceSpend` duplicates an existing fixture body.
- Protect — do not regress:
  - Both existing e2e race tests' user-visible assertions (panel/modal stays open, unsaved edit intact, URL carries `q` + overlay param, `page` reset to 1).
  - Browser Back closes the entry modal onto the searched list (replace+push choreography).
  - The entry modal URL choreography in `app-shell.tsx` (open/close/replace, history back-close, `entryDetailParamRef` restore).
  - Search/filter writes still reset `page` to 1; `writeTransactionFiltersToSearchParams` still owns exactly the filter param names.
  - All currently passing suites stay green.
- Scope exclusions (deliberate; will be filed as separate Kata issues by the operator — do not attempt here):
  - The mirror-direction race: overlay open/close and pagination writes (`use-transaction-detail.ts`, `app-shell.tsx` entry-open, `use-transaction-browser-page.ts` setPage/setPageSize) clobbering a just-committed `q` via the same stale functional updater.
  - Overlay-history semantics for non-search writes (filter/chip/pagination pushes that retain overlay params and change Back behavior).
