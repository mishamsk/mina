# Plan: wkpr review fixes — inline-editor coordination hardening (fix plan 1)

Resolve the operator-review findings in the wkpr inline-editing coordination without regressing the delivered explicit-commit model. Kata issue: `wkpr` (already closed; do not reopen).

## Plan Context

- Do not run review-loop.
- This is an implementation-only fix plan for review findings on branch `wkpr-single-inline-edit`. All file:line references are against the current branch head.
- Protect — do not regress (all verified live and by e2e):
  - Exactly one active inline editor across the shared browser (list, expanded records, detail panel); conflicting interactions discard the draft and are suppressed.
  - Category, tags, member, and amount editors commit only via checkmark Save; Cancel and Escape discard identically; outside click discards.
  - Escape restores focus to the originating cell; while a panel inline editor is active, the first Escape discards the draft and leaves the panel open (per the updated `docs/webui-design.md` Overlays rule).
  - Pending-save draft protection: a failed save keeps the editor open with the draft and an alert (e2e covers a routed 500).
  - Bulk-edit behavior and the memo/posting-status editors are unchanged.
- Scope exclusions: the memo editor's Enter/blur commit model is out of scope (outside the kata's editor set); do not touch `docs/` ground-truth files.
