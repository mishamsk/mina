# Plan: Replace the transaction edit sidebar with a spacious modal editor — Kata `0288`

All transaction creation and saved-transaction editing happens in one centered stage modal (`EntryModal`) opened in place from every entry point; the docked entry panel is removed. Kata issue: `0288`.

## Plan Context

- The design phase is complete. The behavior contract is `docs/webui-design.md` section "3. Transaction entry" plus the updated Overlays, Keyboard, Command Palette, Screen 2 detail, Screen 6 Templates, Screen 8 occurrence bullets, and the `EntryModal` component-inventory entry — all already committed on this branch. The visual contract is the `EntryModal` additions in `docs/webui-theme-arcade-cabinet.md`. Implement exactly these docs.
- Additional implementation detail lives in the untracked working files `design-prototypes/prototype-a.md` and `design-prototypes/judgment.md` (entry-point mapping against real identifiers, graft specifics, rail anatomy). Read both; NEVER commit `design-prototypes/`.
- Reuse the existing entry machinery: the five-tab forms, per-tab IndexedDB drafts, sticky fields, session tally, shorthand-fit logic, and journal grid from `frontend/src/features/ledger/entry-panel.tsx` are re-hosted in the modal, not rebuilt. Shorthand-vs-journal shape selection and edit/save behavior are unchanged except for the surface.
- Scope decisions (operator-approved): the docked `EntryPanel` column is what gets removed; the read-only transaction detail panel STAYS (bn6q will route its Edit here — the detail panel remains open beneath the modal and refreshes after save); expected occurrences stay read-only (no Edit-to-modal); the recurring-definitions editor is out of scope.
- Contracts that must not regress: hf98 bulk mode (opening the modal forces bulk-edit mode off), wkpr inline editing (opening discards an active inline draft; the modal's Esc ladder is self-contained behind its focus trap), 46vf in-place saves and refresh fan-out (saves fan out to the visible list behind the modal), per `frontend/src/features/ledger/PACKAGE.md`.
- This is a major user-visible feature: update `PROJECT_STATE.md` and the ledger `PACKAGE.md` contracts in the delivering commits.
- Targeted ground-truth doc updates are allowed only if implementation genuinely diverges from the documented rule; note any such edit prominently in the completion report.
