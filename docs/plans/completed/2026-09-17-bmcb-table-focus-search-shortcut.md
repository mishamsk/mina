### Design spec

- Initial row focus: on page entry (component mount / route change into the page), once the table has rendered at least one data row, focus the roving active row (index 0, or the URL-restored position if the page already tracks one) with `focus({ preventScroll: true })`. Never focus on later data refreshes, paging, sorting, or filtering — only on entry. Do not steal focus: the attempt is eligible only when `document.activeElement` is `body`, the passive route heading `main h1[tabindex='-1']` (`frontend/src/app.tsx:29` focuses it after bootstrap; `frontend/src/features/app-shell/app-shell.tsx:544` after recurring-editor navigation closure), or an app-shell navigation control outside `main` (a sidebar link or the compact Navigation toolbar trigger that still holds focus after the click or Enter that navigated here — page entry through navigation is the primary case and must land on the first row). It is ineligible when focus is inside an editable control, inside an overlay, or already inside the `main` content region (the user has interacted with the page before rows arrived). There is no general heading-focus effect on every pathname change.
- Skip when a `transaction=` detail deep link is opening (`frontend/src/features/ledger/use-transaction-detail.ts:57` and `frontend/src/features/ledger/transaction-detail-panel.tsx:1016`) or an `?entry=` overlay is open, including before the overlay DOM mounts. Empty and loading tables focus nothing. Wait for the entry's initial result, then consume the attempt whether focused, empty, or blocked; a later refresh or cleared filter must not revive it. Compact shells follow the same rule; `preventScroll` keeps the viewport where it is. Initial focus must not invoke the keyboard-walk `scrollIntoView` path or activation callbacks.
- Visual state of the focused row: exactly the existing roving-tabindex contract — instant hover-style fill on the active row, no focus ring, no border, no geometry change (`docs/webui-theme-arcade-cabinet.md:96`). No layout jump, no scroll, no re-ordering on focus, hover, or modifier state. Retain the existing `--card` / `--band` and `--table-header` hover mixes and `data-active`/focus-within styles; no new tokens or component styling.
- `/` (unmodified, no Shift/Alt/Meta/Ctrl) and `Meta+L` (the platform primary modifier, handled the same way the app already handles `Cmd/Ctrl+S`; the help label follows existing kbd conventions) focus the page's rendered list-search input and select its current text so typing replaces it; both call `preventDefault()` (`/` must not be typed into the field; `Meta+L` must not reach the browser address bar). Match the existing `(event.metaKey || event.ctrlKey)` convention, case-insensitive `l`, without Shift/Alt. Suppressed when `isEditableTarget(event.target)`, when `hasActiveOverlay()` (entry modal, template editor, dialogs, popovers, page help), when the event is already `defaultPrevented`, and when no visible enabled list-search input is rendered (e.g. transaction Edit mode with search unavailable, a compact shell whose search sits inside a closed Controls sheet, register and entity-overview pages). Do not consume suppressed keys or open Controls automatically.
- Placement and states: add a single `data-list-search-input` marker to the existing search inputs; resolve the connected, visible, enabled, non-inert input at keydown time. No new UI surface is added; the search input's existing styling is unchanged (standard 2px `--ring` outline with 2px offset). Search focus changes no value or URL until typing; preserve existing draft/debounce behavior.
- Help: entries read like the existing ones (`docs/webui-design.md` Keyboard + `frontend/src/store/keyboard-shortcuts.ts` shape): two entries labeled `Focus list search`, keys `["/"]` and `["Mod", "L"]`; `frontend/src/components/ui/kbd.tsx` renders `Mod` as `Cmd/Ctrl`. Choose one shared small `List search` group registered by the mounted search components, using the existing shortcut store and `useShortcutGroup`; this avoids copying entries into six table groups and excludes searchless transaction previews automatically. Help is page-aware through search-component lifetime, including empty lists; a compact route may still describe its mounted Controls search, while shortcut dispatch requires that input to be visible. Group ordering in `keyboard-shortcuts-dialog.tsx` is unchanged. Do not add entries to `globalShortcutGroup`.
